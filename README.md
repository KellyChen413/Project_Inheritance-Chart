# 本地端繼承系統表自動產生系統（雛形）

依循《資通安全管理法》與《個人資料保護法》精神設計的離線工具：輸入家族資料，自動判斷法定繼承人、計算應繼分，並產生繼承系統表樹狀圖。

- 全程本機運算，不使用任何雲端 AI API，可於斷網環境執行
- 範例資料全部為虛構，真實戶籍資料不得放入本專案

## 兩個版本

| | 離線網頁版（部署用） | Python 版（開發驗證用） |
|---|---|---|
| 檔案 | `繼承系統表產生器.html` | `main.py`、`inheritance/` |
| 需求 | Edge 或 Chrome 即可，免安裝 | Python、Graphviz |
| 用途 | 帶進內網給承辦人使用 | 開發新規則、批次測試 |

兩版共用相同的基本測試情境（`tests/test_engine.py` 與 `web/test_engine.js`），確保算出的應繼分一致；胎兒、同日死亡、婚姻終止等延伸狀態以網頁版為準（`web/test_qa.js`）。

### 離線網頁版的資安設計

- 單一 HTML 檔，所有程式碼、樣式、範例資料都在檔案內，不引用任何外部資源
- 內建 Content-Security-Policy，瀏覽器層級封鎖所有對外連線（`connect-src 'none'`、`form-action 'none'`、`object-src 'none'` 等）
- 安全政策以 **SHA-256 雜湊值** 只允許檔案內既有的 3 段程式與 1 段樣式執行，不使用 `'unsafe-inline'`；檔案遭竄改或被插入其他程式碼時，瀏覽器會拒絕執行。雜湊值由 `web/build.py` 產生檔案時自動計算
- 資料只存在頁面記憶體，不使用 localStorage、sessionStorage、IndexedDB 或 Cookie（欄位對應設定也只在本次開啟期間記住）；關閉分頁、重新整理或離開頁面時（`pagehide`），主動清空資料，從瀏覽器「上一頁」快取返回時也會清空
- 輸入框關閉瀏覽器自動填入紀錄（`autocomplete="off"`），避免瀏覽器自行保存姓名、統一編號
- 畫面一律以 textContent 輸出文字，不使用 innerHTML、eval，避免輸入內容被當成程式碼執行（DOM 型 XSS）
- 下載檔名只含日期（例：`繼承系統表_1151027.xlsx`），不含姓名，避免下載資料夾的檔案列表洩漏個資
- 列印、Excel、SVG、CSV、案件檔皆由瀏覽器端產生，不傳送任何資料到伺服器
- 輸入檢查：日期格式、死亡早於出生、父母晚於子女出生、親屬關係迴圈等
- 修改原始碼後執行 `python web/build.py` 重新產生 HTML 檔

### 備註與規定說明（網頁版）

- 樹狀圖：拋棄繼承、喪失繼承權以紅色虛線框標示；有特殊狀況者加註 ※ 編號，圖下方備註欄列出完整說明與條文
- 系統表明細：列出所有人（含不繼承者），含存歿、繼承依據、應繼分、備註；同一人有多筆來源（本位＋再轉）時逐筆列出
- 本案適用規定：只列出本案實際用到的規定（代位、再轉、拋棄等）及其要件
- 再轉繼承人可僅就再轉部分拋棄，於「再轉繼承之拋棄設定」勾選

### 兩種輸出格式（網頁版）

- **樹狀圖與明細**：樹狀圖（含 ※ 備註）、拋棄查證紀錄、明細表、適用規定、判斷過程；A4 橫式列印
- **表格式（單張）**：被繼承人資料＋全體人員一覽（稱謂、姓名、統一編號、出生、死亡、繼承情形、應繼分、備註）＋製表日期、承辦人、覆核欄；A4 直式單張列印
- 「下載 Excel」產生 .xlsx（自製產生器，不依賴外部套件），可在 Excel 中再編修
- 統一編號預設遮蔽，勾選「顯示完整統一編號」後，畫面、列印與 Excel 皆顯示完整號碼

### 戶籍資料匯入（網頁版，對應實務流程）

實務上承辦人從戶役政系統調出被繼承人的二親等、三親等關聯資料；子女已死亡時再往下調閱一層，資料遺漏時再調個人戶籍資料。系統對應這個流程：

1. **匯入**：「匯入檔案」可一次選多份 CSV。系統判斷是「親等關聯資料」（有稱謂欄）或「個人戶籍資料」，自動對應欄位，使用者在對應視窗確認後匯入。欄位名稱不同也能手動對應，對應設定在本次開啟期間會記住（只存在記憶體）。
2. **合併**：同一人出現在多份資料時，以統一編號合併；資料不一致（如死亡日期不同）會提示，不會默默覆蓋。
3. **串聯**：依「稱謂（相對於本人）」連結父、母、配偶、子女；其餘關係依父、母、配偶姓名配對（優先同一份檔案中的人）。只補空白的關係，不覆蓋手動設定。
4. **稱謂換算**：戶籍資料的稱謂是相對於各檔的本人，系統依被繼承人重新換算（長男、外孫、次女之配偶…），可手動修改。
5. **待調閱清單**：自動判斷還要調閱誰，例如繼承開始前死亡且查無子女者、繼承開始後死亡（再轉繼承）者、無第一順序時不在資料中的父母。
6. **拋棄繼承查證**：列出各層需查證的繼承人，登錄查證結果、法院、案號、查詢日期；有人拋棄後重新計算並列入遞補者。未完成前，系統表標示「尚非最終結果」。

日期支援戶政常見的 7 碼民國格式（例：0370512）。

範例（全部虛構，統一編號第二碼為 0，不可能是真實號碼）：
- `data/範例1_王大明_二親等資料.csv`：被繼承人的二親等資料（故意漏掉孫女王小平）
- `data/範例2_王淑娟_二親等資料.csv`：再轉繼承人的二親等資料（補上配偶張建國）
- `data/範例3_王小平_個人戶籍資料.csv`：欄位名稱、日期格式都不同的個人戶籍資料

網頁上的「戶籍匯入範例」按鈕會依序匯入這三份，逐步示範。欄位名稱是依「有統一編號、稱謂相對於本人、有父母姓名、死亡日期獨立一欄」推估，實際格式請以戶役政系統匯出檔為準，透過對應視窗調整即可。

測試：`node web/test_hhr.js`

### 介面設計（網頁版）

- 深灰工作列、奶茶色桌面、白色作業面板，搭配內斂的科技藍作為操作色；狀態色（錯誤、提醒、完成）與品牌色分開

- 支援淺色／深色主題（依系統設定）；樹狀圖與表格式維持白紙黑字，列印一律為淺色

- 確認動作（清除、取代、刪除）使用頁內確認視窗

### PDF 匯入（網頁版）

戶政系統匯出的資料若為 PDF，可直接匯入「文字型 PDF」（能用滑鼠選取文字者）：

- 依文字座標還原表格的列與欄；支援跨頁重複表頭、儲存格換行，自動略過標題、查詢條件與頁碼
- 也能讀取「姓名：○○　統一編號：○○」這類表單格式（一份 PDF 一人）
- 還原後進入同一個欄位對應視窗，請核對預覽內容與 PDF 一致後再匯入
- 掃描影像 PDF 沒有文字層，系統會明確提示，不會硬猜（需 OCR，尚未支援）
- 讀取元件為 [pdf.js](https://github.com/mozilla/pdf.js) 3.11.174（Apache-2.0，授權見 `web/vendor/pdfjs-LICENSE.txt`），以主執行緒模式執行；繁體中文字碼表（Adobe-CNS1、Big5、UniCNS 等，約 270 KB）內嵌於頁面，**不需連網**，即使 PDF 使用未內嵌的中文字型也能正確讀出
- 若 PDF 使用未內建的字碼表（例如簡體中文編碼），會提示改用 CSV

範例（虛構）：`data/pdf/`。範例1 使用不內嵌的繁中字型、2 頁且有一格換行；範例2 由 LibreOffice 轉出（內嵌字型）；範例3 為表單格式；範例4 為掃描影像。產生方式見 `tools/make_sample_pdfs.py`。

測試：`npm install pdfjs-dist@3.11.174` 後執行 `node web/test_pdf.js <安裝資料夾> data/pdf`

### CSV 匯入／匯出（網頁版）

範本：`data/繼承資料範本.csv`（或在網頁按「下載 CSV 範本」）

| 欄位 | 填法 |
|---|---|
| 編號 | 可留空，系統自動編號；有同名者時用來區分 |
| 稱謂 | 填「被繼承人」的那一列即為被繼承人 |
| 姓名 | 必填 |
| 性別 | 男／女 |
| 出生日期、死亡日期 | 民國或西元皆可：`民國37年5月12日`、`114/3/10`、`1948-05-12` |
| 父、母、配偶 | 填姓名（同名時填編號），該人必須也在名單中 |
| 拋棄、喪失 | 填「是」＝對被繼承人；填某人姓名＝對該人（用於再轉部分的拋棄） |

- 自動辨識編碼：Excel 一般 CSV（Big5）與 CSV UTF-8 都能讀
- 自動辨識逗號或 Tab 分隔；標題列前可有說明文字；不認得的欄位（如地址）會略過並提示
- 參照不到的人、同名無法判斷時會擋下匯入，並指出 Excel 列號
- 注意：在 Excel 輸入 `37/5/12` 會被誤判為西元 1937 年；民國 100 年以前請寫成 `民國37年5月12日`
- 測試：`node web/test_csv.js`

## 資安範本（精簡版）

`template/繼承系統表產生器_資安範本.html`：約 500 行、32 KB 的單一 HTML 範本，示範如何在實體隔離內網環境下，以純原生 JavaScript 實作繼承系統表。適合交給資訊單位逐行審查，或作為其他內網工具的起點。

- 功能：輸入被繼承人、配偶、子女，判斷第一順序應繼分（民法第1138條、第1144條第1款），以 SVG 畫出樹狀圖
- 輸出：列印、PNG、SVG、PDF；PDF 由程式自行組裝（A4 橫式，不含作者、標題等中繼資料）
- 身分證字號驗證檢查碼；輸出預設遮蔽中段
- 與完整版相同的資安設計：雜湊值 CSP、不使用任何瀏覽器儲存空間、autocomplete 關閉、離開頁面清空、textContent 防 XSS、檔名不含姓名
- 修改範本後雜湊值會改變：用 Chrome 開啟、按 F12，主控台錯誤訊息會提示新的 `sha256-…` 值，替換檔案開頭 CSP 中的對應值即可

完整版（`繼承系統表產生器.html`）涵蓋代位繼承、再轉繼承、後順序繼承人、戶籍資料匯入、拋棄繼承查證等，範本只示範核心架構。

## 架構

```
資料（JSON，之後由 OCR 產生） ──► 規則引擎 engine.py ──► 結果 Result
                                                          ├─► render.py 樹狀圖
                                                          └─► CSV 明細
```

規則引擎與畫圖模組只透過同一份資料結構溝通，換畫圖方式不影響法律邏輯。

## 外部審查與修正（115 年 10 月）

工具曾交由外部技術審查（審查報告聚焦於繼承順位邊界條件與程式防呆）。依審查意見逐條判斷後修正如下（網頁版）：

| 審查意見 | 處理 |
|---|---|
| 第 1176 條第 5 項次親等遞補不應「無條件往下一代」 | 改為明確的分支狀態（本位／代位／拋棄／非繼承人）。只有「得繼承者均拋棄」時才往次親等，且只往拋棄者的子女；判斷過程逐一列出 |
| 代位繼承限第一順位繼承人先死亡或喪失繼承權 | 維持並以測試固定：拋棄者子女不代位、被代位人之配偶不代位、第二至第四順序不代位 |
| 胎兒權利 | 新增胎兒狀態（待出生／已活產／死產），待出生者保留應繼分並標示待確認 |
| 同日死亡不得一律推定同時死亡 | 新增死亡時間；可證明先後者依實際先後判斷，否則依第 11 條推定並列為待確認 |
| 祖父母重複計數、重複 ID | 祖父母以 ID 去重；重複 ID 於驗證及建立家族時阻擋 |
| 分數安全 | 分母為零、非整數除數、超出安全整數範圍時拋出錯誤 |
| 查無繼承人不等於無人承受 | 改為「目前查無繼承人」，並提示確認無人承受前應完成親屬調查 |
| 拋棄繼承須區分已聲明與已核實 | 查證結果新增「已聲明拋棄（待核實）」，納入計算但標示待核實 |
| 有待確認事項時不得輸出無警告的確定結果 | 所有待確認事項彙整於案件狀態，並顯示在樹狀圖、表格式、Excel |
| 婚姻關係 | 新增婚姻終止日；於繼承開始前終止者不具配偶繼承權 |
| 規則版本 | 頁尾與表格式顯示規則版本 |

**與審查報告見解不同之處：** 報告 QA-09 案例（甲拋棄且有子女、乙繼承開始前死亡且無後代）認為不應遞補。本工具採以下見解：乙先死亡又無人代位，本非繼承人，第 1176 條第 5 項所稱「親等近者均拋棄」只就得繼承之人判斷，因此甲拋棄即構成均拋棄，由甲之子女（次親等）與配偶共同繼承。此為本工具的法律判斷，判斷過程會完整列出，正式案件仍應由承辦人覆核。

**已知限制：** 配偶仍以單一婚姻關係建模（可記錄該婚姻的終止日），尚未支援同一人多段婚姻的完整紀錄；Python 版僅同步修正重複 ID 與祖父母去重，胎兒、同日死亡、婚姻終止等新狀態以網頁版為準。

QA 測試：`node web/test_qa.js`（審查報告 QA-01～QA-15 及延伸案例，共 27 項，表格驅動）

## 已實作的民法規則

| 條文 | 內容 |
|---|---|
| 第 1138 條 | 繼承順序：配偶＋直系血親卑親屬／父母／兄弟姊妹／祖父母 |
| 第 1139 條 | 第一順序以親等近者為先 |
| 第 1140 條 | 代位繼承（繼承開始前死亡、喪失繼承權） |
| 第 1144 條 | 配偶應繼分（平均／1/2／2/3／全部） |
| 第 1176 條 | 拋棄繼承不發生代位；第一順序親等近者均拋棄時由次親等繼承 |
| 第 11 條 | 同時死亡推定，互不繼承；同日死亡可填時間判斷先後，先後不明時列為待確認（網頁版） |
| 再轉繼承 | 繼承人於繼承開始後死亡，其應繼分由其繼承人再繼承（同日較晚死亡者亦同，網頁版） |
| 第 7 條、第 1166 條 | 胎兒以非死產為限視為既已出生，保留其應繼分；待出生／已活產／死產三種狀態（網頁版） |
| 第 1144 條（配偶身分） | 婚姻於繼承開始前終止（如離婚）者，不具配偶繼承權（網頁版） |

## 資料格式

```json
{"id": "P11", "name": "王志偉", "title": "次男", "birth": "1975-06-30", "death": "2020-06-01",
 "father": "P01", "mother": "P02", "spouse": "P30", "renounced": [], "lost_right": []}
```

`renounced` / `lost_right` 填入被繼承人的 id，表示對該被繼承人拋棄繼承或喪失繼承權。

字型：預設 Noto Sans CJK TC；Windows 可改 `render.py` 的 `FONT = "Microsoft JhengHei"`。
